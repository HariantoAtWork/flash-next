# Auto detect gpu group ids in dc.sh

`flash-next` runs privileged and adds the host `video` and `render` groups via
`group_add`, which read `VIDEO_GID` and `RENDER_GID`. These vary per host (for
example amdgpu setups commonly use 26 and a four-digit render id), so the
compose defaults were frequently wrong.

`dc.sh` now resolves both ids before `up` and `restart` from `/dev/dri/card0`
and `/dev/dri/renderD128`, falling back to the named groups from `getent`, and
warns when a value cannot be determined. The compose defaults stay untouched
and an explicit `VIDEO_GID`/`RENDER_GID` in the environment still wins.

`restart` was switched to `up -d --force-recreate` so the newly resolved group
ids actually take effect, since group membership is fixed at container create
time.
